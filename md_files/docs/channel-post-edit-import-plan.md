# خطة تعديل منشور قناة أو استيراده

> الحالة: مسار تعديل/استيراد المنشور وتحسين موضع البلوكات نُفذا ونُشرا إلى Telegram Serverless في 2026-10-16، revision 80؛ إصلاح إيموجي زر الحفظ وتنظيف رسالة الاختيار أدناه محليان وغير منشورين.

## الهدف وتجربة المستخدم

عندما يرسل المستخدم إلى البوت منشوراً محوّلاً من قناة يستطيع البوت إدارتها وتعديل منشوراتها، يتحقق البوت من مصدر المنشور وصلاحياته ثم يعرض:

> «عندي وصول للقناة وأكدر أعدّل المنشور. شتريد تسوي؟»

تصل رسالة جديدة مستقلة لكل تحويل، مع زرين:

- **تعديل المنشور**: يفتح المحرر بمحتوى المنشور المستهدف، ويحوّل زر «مزامنة الصفحة» في لوحة المحرر إلى زر **تعديل المنشور**. لا يتغير المنشور في القناة إلا بعد ضغط المستخدم على هذا الزر.
- **استيراد الصفحة**: يتابع مسار الاستيراد الحالي؛ يفتح المحرر بمحتوى المنشور المحوّل كمسودة مستقلة غير مرتبطة بتعديل أصل القناة.
- تُحذف رسالة اختيار الإجراء بعد نجاح فتح المحرر، بما في ذلك بعد تأكيد استبدال مسودة موجودة؛ لا تبقى الرسالة القديمة بجانب لوحة المحرر.

أضف نصوصاً مترجمة لكل اللغات المدعومة مع الحفاظ على صياغة العربية المعتمدة. لا تذكر أو تغيّر وضع الإنلاين المعطّل.

## الوضع الحالي ونقطة الانطلاق

- يستقبل المسار الخاص الرسائل الغنية المُحالة، ويتعرف عليها `isForwardedRichMessage` في `tgcloud/lib/editor-core.js`.
- يُحوّل `parseRichMessage` محتوى الرسالة إلى كتل، ويعرض تحذيراً قبل استبدال مسودة موجودة.
- يفتح زر `r:syncpage` حفظ الصفحة إذا لم يكن لها معرّف محفوظ، ويعرض «حفظ» مع الإيموجي المخصص `5188563846415014158`؛ بعد الحفظ يعرض «مزامنة الصفحة» ويزامن عبر `syncSavedEditorPage` في `tgcloud/lib/editor-pages.js`. وجود هدف منشور قناة يبقي أولوية زر «تعديل المنشور».
- يحتفظ `editor-session` بحالة المحرر في Telegram Serverless؛ تبقى الصفحة الأصلية والاشتراكات والصفحات المحفوظة تحت مصادر الحقيقة الحالية.

## متطلبات التنفيذ

1. **تحديد المصدر بأمان**
   - استخرج هوية القناة ومعرّف الرسالة من بيانات الإحالة المتاحة في Telegram؛ ارفض الإحالات المخفية أو الناقصة أو التي لا تمثل منشور قناة قابلاً للتحرير.
   - تحقق من وصول البوت إلى القناة ومن صلاحية تعديل المنشورات قبل عرض خيار التعديل، وأعد التحقق عند محاولة الحفظ.
   - لا تعتمد على عنوان القناة أو نص الرسالة لإثبات الهوية أو الملكية.
   - تحقّق من قدرات Telegram Serverless وواجهة Bot API الفعلية لتعديل الرسائل الغنية، والوسائط، والأزرار. إذا تعذر تعديل نوع محتوى معين، اعرض سبباً واضحاً واترك خيار الاستيراد متاحاً.

2. **عرض الاختيار**
   - أرسل رسالة جديدة مستقلة لكل تحويل في المحادثة الخاصة، مع زري تعديل المنشور واستيراد الصفحة؛ لا تستبدل رسالة لوحة المحرر أو رسالة تحويل سابق.
   - إذا كانت هناك مسودة أو عملية تحرير نشطة، اطلب موافقة إضافية قبل إغلاق المحرر وحذف محتواه غير المحفوظ. وضّح أن الصفحات المحفوظة لن تتأثر؛ الرفض يعيد المستخدم إلى حالته السابقة دون تغييرها.
   - بعد الموافقة، أغلق جلسة المحرر الحالية وامسح المسودة غير المحفوظة، ثم أرسل رسالة اختيار التعديل/الاستيراد كرسالة جديدة.
   - احذف رسالة تحذير إغلاق المحرر بعد اختيار المتابعة أو الرفض.
   - اربط callback بالمستخدم والرسالة المصدرية المسجلين، واجعل إعادة الضغط أو انتهاء الجلسة آمناً وواضحاً.
   - ترجم النص والزر والتنبيهات ورسائل فشل الصلاحيات لكل اللغات المدعومة.

3. **جلسة تعديل المنشور**
   - خزّن ضمن جلسة المحرر فقط مرجع المصدر اللازم: معرّف القناة، معرّف الرسالة، نوع المحتوى/الوسائط، وبيانات تحقق من النسخة الأصلية. لا تنشئ مخزن صفحات ثانياً في D1.
   - حمّل المحتوى إلى محرر قابل للتعديل مع الاحتفاظ بما يمكن دعمه من التنسيق والوسائط والأزرار.
   - اعرض زر «تعديل المنشور» بدلاً من «مزامنة الصفحة» في سياق هذا المصدر فقط؛ تبقى مزامنة الصفحات المحفوظة كما هي للمستخدمين الآخرين.
   - بعد نجاح تعديل المنشور، احتفظ بمرجع المنشور في جلسة المحرر كي يبقى زر «تعديل المنشور» متاحاً للتعديلات اللاحقة.
   - عند الضغط، أعد التحقق من صلاحية القناة. واجهة Telegram المتاحة لا تسمح للبوت بقراءة النسخة الحالية للمنشور أو مقارنة نسخة/مراجعة؛ لذلك لا يمكن اكتشاف تعديل المصدر بعد تحويله.
   - اعرض تحذيراً واضحاً قبل التأكيد النهائي بأن تغييرات المصدر اللاحقة لا يمكن التحقق منها وقد يستبدل التعديل النسخة الحالية. لا تعدّل القناة إلا بعد تأكيد صريح ثانٍ.
   - استخدم واجهة التعديل المعتمدة لدى Telegram، وحرر الرسالة الموجودة من دون إرسال منشور مكرر. لا تحذف النسخة الأصلية عند الفشل.
   - لا تسمح لتجاوز حد الخطة الداخلي بتوسيع المحتوى المخزّن دون تأكيد السياسة المعتمدة، ولا تتجاوز حدود Telegram أو صلاحياته.

4. **مسار الاستيراد**
   - ينفذ «استيراد الصفحة» مسار `rich_import_replace` الحالي كما هو، بما فيه تحذير استبدال المحتوى المفتوح.
   - تبقى المسودة المستوردة غير مرتبطة بمصدر القناة؛ لا يظهر لها زر تعديل المنشور ولا يجري تعديل القناة عند حفظ صفحة أو نشر عادي.

## اختبارات ومعايير القبول

- يظهر الاختيار فقط للمصدر القابل للتحقق الذي يملك البوت صلاحية تعديله؛ ويظل الاستيراد متاحاً عند تعذر التعديل متى أمكن قراءة المحتوى.
- كل تحويل ينشئ رسالة اختيار جديدة؛ المحرر النشط لا يُغلق ولا تُحذف مسودته إلا بعد موافقة إضافية، والرفض يحفظ المسودة وحالة التحرير.
- تحذف رسالة تحذير إغلاق المحرر بعد الاختيار، ويبقى زر تعديل المنشور ظاهراً بعد أول تعديل ناجح.
- خيار الاستيراد يفتح مسار المحرر الحالي ولا يغيّر القناة أو الصفحة المحفوظة.
- خيار التعديل يفتح نفس المحتوى، ويظهر زر التعديل بدلاً من مزامنة الصفحة، ويحدّث المنشور الأصلي مرة واحدة بعد فعل صريح من المستخدم.
- إعادة callback، انتهاء الجلسة، فقدان صلاحية المستخدم أو البوت، وحذف/تعذر تعديل المنشور لا ينتج عنها منشور مكرر؛ تُعاد مراجعة صلاحية التعديل عند التأكيد النهائي.
- لأن Bot API لا يتيح قراءة النسخة الحالية أو CAS، لا يمكن ضمان اكتشاف تغيير المصدر بعد التحويل. يظهر تحذير ذلك ويجب أن يؤكد المستخدم التعديل صراحةً.
- اختبارات الأنواع المدعومة وغير المدعومة تشمل النص والتنسيق والوسائط والتعليقات والأزرار بقدر ما تسمح به واجهة Telegram.
- تغطي اختبارات التوطين كل اللغات المدعومة، وتُشغّل مجموعة اختبارات Serverless ذات الصلة وفحوصات النشر البرمجية.
- لا migration أو نقل لمحتوى القنوات إلى Cloudflare/D1. لم يتطلب النشر تغيير webhook.

## التنفيذ والحد المعروف

- بدأ التنفيذ بطلب المالك في 2026-10-16. عند وجود صلاحيات تعديل لدى البوت والمستخدم تظهر خيارات تعديل المنشور أو استيراده. خيار التعديل يحمل سياق المنشور داخل جلسة المحرر، ويبدّل زر مزامنة الصفحة إلى تعديل المنشور؛ الاستيراد يبقى مستقلاً.
- كل تحويل يرسل رسالة اختيار جديدة. عند وجود محتوى أو عملية نشطة، تسبقها موافقة إضافية توضّح إغلاق المحرر وحذف المسودة غير المحفوظة؛ إلغاء التحذير يعيد حالة المحرر السابقة، والموافقة تمسح الجلسة فقط ولا تمس الصفحات المحفوظة ثم تتابع الاختيار.
- متابعة إصلاحية: تحذف رسالة تحذير الإغلاق بعد الموافقة أو الرفض، ويبقى مرجع المنشور مربوطاً بالمحرر بعد نجاح التعديل كي لا يعود الزر إلى مزامنة/حفظ الصفحة.
- يتطلب التعديل تحذيراً نهائياً وموافقة أخرى. قبل المحاولة يعاد فحص صلاحيات الطرفين؛ وعند فقدها يُلغى هدف التعديل. الإلغاء العادي يحافظ على الهدف ليتمكن المستخدم من المتابعة لاحقاً.
- أكد المالك قبول عدم إمكانية اكتشاف تعديلات المصدر التي تحدث بعد التحويل، وطلب تحذيراً وموافقة نهائية قبل المتابعة. لا يدعم Telegram Bot API قراءة المنشور الحالي أو شرط نسخة/مقارنة ذرية؛ لذا قد يستبدل التعديل اللاحق محتوى أحدث.
- في متابعة لاحقة، رُفعت رسائل الخيار المنفصلة وتحذير إغلاق المحرر مع تأكيده إلى revision 77؛ الحالة بعد الرفع كانت webhook in sync وWorking directory clean.
- في متابعة لاحقة ثانية، حُذفت رسالة تحذير إغلاق المحرر بعد الاختيار، وأُبقي سياق المنشور بعد التعديل الناجح؛ رُفع `editor-core.js` وحده إلى revision 78، والـwebhook in sync وWorking directory clean.
- لا schema change أو migration. رُفعت الوحدات الـ29 المحددة، وأكد `npm.cmd run status` revision 76، والـwebhook in sync وWorking directory clean.

## خارج النطاق

- تعديل المنشورات التي لا يملك البوت صلاحية تعديلها أو التي لا يمكن تحديد مصدرها بثقة.
- حفظ نسخ تاريخية للمنشور أو إنشاء نظام قوالب/إصدارات للصفحات.
- النشر التلقائي أو تعديل القناة بمجرد فتح المحرر، دون ضغط المستخدم على زر التعديل.
