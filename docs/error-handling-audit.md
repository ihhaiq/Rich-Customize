# تدقيق معالجات الأخطاء — Rich Customize

التاريخ: 2026-10-10 — الفرع `serverless-cleanup`

## النطاق

تمت مراجعة معالجات Telegram Serverless (الرسائل، الأزرار، Inline، وضع الضيف، القنوات، التحقق من الدفع)، مسارات النشر والجدولة، المحرر، الإيموجي، الترخيص المدفوع، جسر Mini App، واستجابات Cloudflare API. يشمل التغيير الشيفرة المذكورة في `log.md` واختبارات الانحدار الجديدة.

## سياسة التعامل

1. **رفض متوقع من تليكرام:** أبلغ المستخدم بالسبب والإجراء المطلوب، ولا تعاود تنفيذ Callback تلقائياً ولا تحذف وجهة بسبب فشل شبكة مؤقت.
2. **فشل مؤقت/نتيجة غير مؤكدة:** لا تفترض فشل إرسال المنشور بعد انقطاع الشبكة؛ قد تكون الرسالة وصلت. لا تنشئ تكرارات بالإعادة العمياء.
3. **خلل في التطبيق:** سجل الاستثناء الأصلي والسياق بعد تعقيم الأسرار، وأظهر للمستخدم نصاً آمناً دون تفاصيل داخلية.
4. **الدفع:** لا تقبل PreCheckout لا يمكن التحقق منه. احتفظ بإمكانية إعادة معالجة إشعارات الدفع إلى أن يثبت إنشاء الترخيص.
5. **التطبيق المصغر:** أخطاء 5xx تتخذ نموذج `{ok:false,error:{code:'SERVICE_UNAVAILABLE',message},retryable}`؛ أخطاء المدخلات 4xx تحتفظ باستجاباتها الحالية.

## الحالات التي لها إرشاد واضح

- `TOPIC_CLOSED`، `TOPIC_DELETED`، `MESSAGE_THREAD_ID_INVALID`
- `RICH_MESSAGE_TABLE_COLS_TOO_MANY` وحدود المحرر، وبيانات بلوك/ملف ناقصة
- `RICH_MESSAGE_EMOJI_INVALID`، `STICKERSET_INVALID`
- انتهاء صلاحية Callback، `message is not modified`، وتزامن أو فشل تعديل رسالة قديمة
- `429 retry_after`، صلاحيات البوت، الوجهة غير المتاحة، ملفات الميديا والأزرار
- أخطاء الشبكة وانتهاء المهلة، وملفات ZIP/JSON التالفة
- `ReferenceError` و`TypeError` وبقية الأخطاء غير المصنفة: **لا تُخفى عن المطور**؛ تعرض للمستخدم رسالة عامة وتحتفظ بالتفاصيل في السجل.

## التحقق

- ملفات الاختبارات: `operational-errors.test.mjs`، `pre-checkout-recovery.test.mjs`، `managed-bot-payment-recovery.test.mjs`، `http-error-safety.test.mjs`، `static-error-guards.test.mjs`، إضافة للاختبارات السابقة.
- تحقق مستقل من 10 حالات تصنيف، و4 حالات PreCheckout بمحاكيات API، وحالتي إصدار الترخيص أول مرة واستكمال الدفعة السابقة، وفحوص صياغة للملفات المعالجة. **هذا ليس بديلاً عن `npm test` أو اختبار تليكرام الحي.**
- GitHub Actions: سير العمل `A1 subscription quotas tests` ظاهر بحالة **failure** على الفرع؛ توجد إخفاقات في سجل تشغيل يعود إلى ما قبل هذه الجولة (مثلاً commit `1b83d3b79`). لم تتوفر ملفات سجل Jobs من واجهة GitHub الموصولة (`BlobNotFound`). يجب تحديد سبب الفشل وتشغيل المجموعة الكاملة قبل الإنتاج.

## حدود الضمان ومتابعة العمل

لا يمكن ضمان عدم حدوث استثناء جديد مستقبلاً، ولا إرسال إشعار Telegram إذا تعطلت قاعدة البيانات وقناة التنبيهات والشبكة معاً. الهدف هو عدم ترك خطأ معروف بلا شرح، مع بقاء الأعطال الجديدة مرصودة بدل إخفائها.

ما يزال الاختبار الحي مهماً خصوصاً لمسار Telegram Stars (التحقق من الدفع وحالات التفعيل الجزئي)، وتزامن تعديل الرسائل، ونتائج الجدولة المجهولة، وتجربة عرض رسالة `SERVICE_UNAVAILABLE` في التطبيق المصغر. لا تنفذ `tgcloud push` أو نشر Cloudflare إلى الإنتاج دون اجتياز الاختبارات ومراجعة الفروقات.
