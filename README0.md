Telegram Rich Message Editor

بوت Telegram مبني باستخدام Python وAiogram لتحويل الرسائل إلى محرّر Blocks، ثم تعديلها ومعاينتها ونشرها كرسائل غنية في الخاص أو القنوات والمجموعات.

يدعم المشروع استقبال Message.rich_message الحقيقي، النصوص المنسقة، الوسائط والألبومات، مع إدارة Blocks والأزرار الشفافة والنشر المتعدد.

المزايا

محرّر Rich Message

استقبال Rich Message وتقسيم كل Top-Level Rich Block إلى عنصر مستقل.

استقبال النصوص والوسائط والألبومات المرسلة من المستخدم.

تعديل محتوى Block أو حذفه أو تغيير موقعه.

إضافة Blocks جديدة إلى الرسالة الحالية.

معرّف ثابت لكل Block يمنع أخطاء الأزرار القديمة بعد إعادة الترتيب.

حذف مؤكد وحماية من الضغط المتكرر أثناء العمليات الحساسة.

إرسال النتيجة كرسالة غنية واحدة باستخدام sendRichMessage.

معاينة النتيجة في الخاص قبل النشر.

عرض Thinking مؤقت باستخدام sendRichMessageDraft أثناء تجهيز المعاينة.

يحافظ المحرّر على تنسيقات Telegram المدعومة، ومنها:

العريض والمائل وتحته خط والمشطوب.

Custom Emoji عندما تسمح صلاحيات Telegram بذلك.

Marked وSubscript وSuperscript في Rich Text.

الاقتباسات العادية والاقتباسات البارزة.

إذا احتوى النص العادي على اقتباس Telegram، يقسمه المحرّر إلى Paragraph وBlockquote مستقلين. يحافظ هذا على الاقتباس عند إضافة Blocks أخرى أو عند وضعه داخل Details.

Popup تنبيه

ينشئ زر Callback يعرض تنبيهاً داخل Telegram عند الضغط عليه. الحد الأقصى للنص 200 حرف.

كل معاينة أو عملية نشر تحصل على رمز Popup مستقل، لذلك لا يؤدي تعديل المسودة إلى تغيير نص التنبيه في المنشورات القديمة. يجب أن يكون البوت قيد التشغيل حتى يجيب عن ضغطات Popup.

الإرسال المتعدد

يمكن تحديد عدة محادثات في كل عملية:

⬜ تعني أن المحادثة غير محددة.

✅ تعني أن المحادثة محددة.

الضغط على المحادثة يبدّل حالتها.

بعد الإرسال يعرض البوت تقريراً بعدد المحادثات الناجحة والفاشلة. فشل محادثة واحدة لا يوقف الإرسال إلى البقية.

التخزين الدائم

يستخدم المشروع ملفات JSON للقنوات وPopup وShowcase وحالة ملف البوت. نظام الملفات المؤقت قد يُمسح عند إعادة النشر، لذلك يفضّل إنشاء Railway Volume وربطه بالمسار:

/data

ثم استخدم:

MANAGED_CHATS_STATE=/data/managed_chats.json
BUTTON_POPUPS_STATE=/data/button_popups.json
BOT_PROFILE_STATE=/data/bot_profile_state.json
SHOWCASE_MEDIA_LIBRARY=/data/showcase_media.json

عدد النسخ

المشروع يعمل حالياً باستخدام Long Polling وMemoryStorage. شغّل نسخة واحدة فقط من الخدمة؛ تشغيل أكثر من Replica على التوكن نفسه يسبب تعارض Polling، كما أن جلسات المحرّر لا تتشارك بين النسخ.

للتوسع لاحقاً استبدل MemoryStorage بـRedisStorage، وانقل سجلات JSON إلى قاعدة بيانات مشتركة.

مسؤولية الملفات الأساسية

main.py: إنشاء Dispatcher، تسجيل Middleware وبدء Polling.

app/config.py: تحميل .env ومتغيرات البيئة.

app/routers/rich_editor.py: أوامر البوت وHandlers وحركة المستخدم داخل المحرّر.

app/keyboards.py: جميع Inline Keyboards.

app/i18n.py: اللغة والترجمة وضبط ملف البوت.

app/services/parser.py: تحويل الرسائل وRich Messages إلى Blocks داخلية.

app/services/renderer.py: بناء InputRichMessage وإرسال المعاينة والمنشور.

app/services/blocks.py: تعديل Blocks وحذفها وإعادة ترتيبها وإدارة خلايا الجداول.

app/services/buttons.py: أنواع الأزرار والتحقق من الروابط والترتيب.

app/services/albums.py: تجميع عناصر media_group_id قبل تحويلها.

app/services/chat_registry.py: حفظ محادثات النشر والتحقق منها.

app/services/popup_registry.py: حفظ نصوص Popup المنشورة.

app/services/media_library.py: حفظ file_id لوسائط Showcase.

app/services/showcase.py: إنشاء قالب جميع Rich Blocks.

ملاحظات أمنية

لا تنشر BOT_TOKEN في GitHub أو السجلات أو ملفات المشاركة.

امنح البوت أقل صلاحيات إدارية يحتاجها.

لا تثق بروابط المستخدم دون التحقق منها؛ المشروع يقبل فقط مخططات URL المحددة.

ملفات JSON قد تحتوي معرّفات محادثات ونصوص Popup، لذلك لا تنشر مجلد البيانات.

حالة المشروع

المشروع جاهز للتشغيل الفردي باستخدام Long Polling. للاستخدام الإنتاجي طويل المدى يُنصح بإضافة Redis للجلسات وقاعدة بيانات مشتركة للسجلات، مع إبقاء خدمة Polling بنسخة واحدة لكل Bot Token.
